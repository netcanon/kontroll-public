# node_exporter — host metrics agent (an ACTION role, not a device class)

Installs the Prometheus **node_exporter** (host CPU/mem/disk/net) on a Linux host, **dispatching by OS
family** — the fleet is mixed (Debian: Proxmox / OpenMediaVault hosts → `apt`+`systemd`; Alpine: e.g. a reverse-proxy pair → `apk`+OpenRC). The
package is `prometheus-node-exporter` on both. Unlike the device-class roles (`proxmox`, `cisco_ios`, …) it
has **no `check`/`backup` entrypoint** — it is not a managed device class, it is an action applied to a
host. Entrypoint `tasks/main.yml` dispatches to `tasks/Debian.yml` / `tasks/Alpine.yml`; an unsupported OS
family **fails loudly** (never a silent skip).

## Where it fits
The observability paradigm splits two ways by a class's `module.yml` `metrics:` block:
- **`via: host`** (Linux hosts — proxmox, docker_host) → the host runs node_exporter → **this role installs it.**
- **`via: proxy`** (pve-exporter / snmp / blackbox) → a control-node exporter queries the device → nothing installed here.

The scrape **target** for the host is GENERATED by `scripts/gen-observability.py` (from the module +
inventory); this role just lands the agent so that target goes from DOWN → UP.

## Invocation
- **Backfill the fleet:** `ansible-playbook playbooks/install-node-exporter.yml --check --diff` (then for real).
- **One host (onboard):** `ansible-playbook playbooks/install-node-exporter.yml -e target=<host>`.

## Blast radius / safety
| Aspect | Value |
|---|---|
| Access chain | control VM (mgmt VLAN) → target host (SSH, root key) |
| Blast radius | the targeted host(s) — adds a node_exporter service + `:9100` listener |
| Reversible | yes — `apt remove` / `apk del prometheus-node-exporter` |
| Idempotent | yes — package `present` + service `enabled/started` → 0 changed on re-run |
| Security | `:9100` exposes host internals (sensitive, not secret) — mgmt/server-VLAN-only, never WAN (SECURITY.md C3) |

## Defaults (`defaults/main.yml`)
Package is `prometheus-node-exporter` on both families; `defaults/main.yml` carries the per-OS package list
+ service name (Debian systemd unit `prometheus-node-exporter`; Alpine OpenRC service `node-exporter` from
the `-openrc` package). Override in `host_vars/<host>.yml` for an odd layout or a restricted listen address.
A new OS family = add `tasks/<Family>.yml` + its defaults (the role fails loudly until you do).
